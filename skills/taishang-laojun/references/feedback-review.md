# 发布后：比较目标与实际

读用户原本想让谁理解什么、希望发生的行动，以及实际评论、咨询、数据或本人反馈。只有播放数不能判断观众动机；缺哪种证据就说明未知，不要求一次补齐所有后台资料。

依次比较：
1. 选题吸引了谁，是否匹配目标；来要成品、求职、学习、看热闹都先视为待核分类。
2. 开头与画面承诺了什么，后面是否兑现；中段是否有清楚行动和递进。
3. 标题是否补足内容，还是让人产生了不同预期。
4. 结尾希望观众做什么，实际想找你解决什么。

给出一个有证据的优先解释和必要替代解释，说明如何区分；不要把单条低播放直接归因标题或时长。

提出最小调整，交总入口选择看火/开炉/回炉/收丹；只有涉及商业目标才进成丹。也可以顺着真实需求做下一条答疑，但先核对本人是否愿意且能交付。推荐动作要说明观察哪种反馈；没有实际复测结果就不称改善已验证。

## 把这次判断接到下一次

先区分未发布、已发布但反馈不足、有实际反馈三种情况。未发布只诊断内容；信息不足时指出能判断和不能判断的部分，最多追问最影响结论的一项信息，不强迫提交整套后台截图。

用简短记录串起：本次目标及对应作品/版本、发布后的观察区间、已有数据或真实反馈、暂时解释、下一条优先改哪一点，以及准备观察什么。已有记录则续写；未知项省略或标未知，不把记录表当用户必填作业。播放、涨粉、咨询、成交分别判断；生活记录可以看表达是否符合本人意图，不强加商业指标。

每次优先检验一个可调整因素，尽量保留其他条件便于比较。下次反馈回来再对照原判断；若发布时间、题材或流量来源等也变了，说明不能单独归因。表现变好只是一次观察，不能立即升级为通用爆款规律。没有后续反馈就保留“待验证”，不反复催用户交数据。

不自动要求提高发布频率或模仿热门风格；调整要兼顾本人表达偏好、实际时间和拍摄资源。需要留存时遵循总入口的个人素材保存边界。
