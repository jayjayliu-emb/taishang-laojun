# 成丹：变现承接

先区分曝光、需求与成交，再决定下一步。不把纯生活记录者强行变成卖课者，也不把柳爷选择开源项目的个人路线要求给所有行业。

## 三个诊断角度

- **预期用户 ≠ 实际用户**：原本想吸引谁，实际评论/咨询者在要什么？展示结果可能吸引想直接要结果的人，展示过程可能吸引学习者，但需看真实反馈，不据此断言所有人的动机。
- **过程终点**：内容最后让观众期待的是成品、方法、服务还是交流？与想提供的帮助一致吗？不一致时调整展示重点、证据或结尾，而不只是换标题。
- **三层分离**：点赞者、咨询者、付费者分开看。没有咨询/成交资料就写未知，不把粉丝等同潜在付费客户。

**事件驱动与成交理由**：以咨询/服务为目标的账号，每条内容尽量挂在一件具体真实事件上；事件的功能是展示判断力，落点是让观众产生明确的"我可以去找他"的理由。纯生活记录或不做服务承接的账号不强套此链。

**动手前三问**：要做工具/项目时，先回答——成熟同类覆盖了什么、我的差异点是什么、用户为什么选我。答不出就不做同类竞争，改做互补：挂在成熟品旁边，解决它不管的那一段。

## 工作流程与交付

1. 读商业目标、已有内容与实际反馈；只有数据、没有需求时先判断缺什么。
2. 找一个能兑现的交付：现成产品、教学、咨询或定制服务均可。标准化可能省重复沟通，但不自动优于所有非标服务；估算本人交付与售后成本。
3. 先用小范围试用/需求确认或透明的付费试验验证。没有成交记录不声称已验证市场，也不默认必须低价出售。
4. 根据所在平台、地区和可用功能选择官方允许的承接渠道。GitHub、主页、评论区或群都不自动等于合规；需要判断当前平台规则时查官方资料，无法核实时明确待核，不提供规避方案。
5. 输出：实际需求与目标的差异、建议尝试的一个交付、承接方式及依据、需观察的反馈、何时停止或调整。只有用户要求话术时再写，按已有个人口吻表达。

**项目/作品命名四查**（给工具、开源项目或系列起名时用）：①普遍认知——借大家已认识的形象，零解释成本；②记忆点——有趣/反差优于正确；③一针见血——名字加一句话功能能戳中对方想象不到的痛点；④查重——在目标平台搜索确认不撞名。

不承诺收入、流量或“一定能接广告”；不虚构案例，不参与违法或害人的业务。保留柳爷对不愿服务人群的边界意识，但不擅自替用户推断价值观或把合法正常沟通一概禁止。
