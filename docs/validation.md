# 0.5.0 验证范围（2026-10-26）

基础版本：8c9895d（0.4.0，含改稿六刀）。本轮按 41 轮原始语料和 REA 复盘重修全部技能。语料到技能的逐条对应保存在私有库的《语料提炼地图》，不随公开包分发。

## 本轮改了什么

- 总入口改为“AI 先下判断、用户校准”，每次落到一件今天能做的事，加入“换个人还成立就重做”的反模板自检；底线规则集中写一次，不再在每个模块里重复。
- 新增炉心（七条底层判断，每条按“观众那边 → 所以 → 柳爷怎么做 → 条件变了 → 误用”展开）和推理示范（九条视频的决策链，不含播放涨粉数据和个人经历细节）；原“创作观察”并入炉心。
- 看火加入选题决策链、四种吸引力、会招来谁、串联；开炉围绕破冰、勾证衔接与钩子链、信息打包、两个理由重写；选材扩展到找对标和选工具；收丹补陌生人视角与两个反面标题；成丹加入纠偏/顺势/拒绝三条路和交付成本；访谈改为“问决定，不问定义”，并覆盖替老板做号。
- 改稿六刀：平台推流说法改为柳爷的观察；承接规则与成丹统一；明确是成稿之后的工序。
- 全景图改由 `scripts/build_mindmap.py` 生成，两份 HTML 与 SVG 同源，`check_package.py` 会发现不同步；新增 Bot 精简版。

## 本轮已完成

- `check_package.py`：七个技能身份、隔离安装引用、仓库链接、配方全集、两份 Bot、全景图与随包声明同步检查通过。
- `test_portability.py`：GBK 默认编码与 Windows 路径模拟两项回归通过；运行环境为 macOS。
- 全景图 SVG 与交互版 HTML 在浏览器中做了渲染查看。

## 盲测（2026-10-26）

- 方法：测试员只拿到 Bot 文件和虚构用户请求，按文件规则写第一条回复；评审员不知道哪条来自哪个版本，回复顺序逐场景随机，按“先下判断、落地、私人定制、讲清观众心理、不套模板、诚实、交付匹配”七项打分。
- 第一轮：0.4.0 对比 0.5.0 初版，六个场景（理发店新手、宝妈借参考、修车整稿、宠物医生标题、烘焙招课复盘、替五金厂老板做号）里 0.5.0 全部胜出，修车整稿一项只是略胜。评审指出的问题：素材不够时不给示范、框架术语直接丢给用户、医疗类标题丢了危险信号、整稿重复同一事实、把推断当事实。
- 第二轮：修正后版本对比 0.5.0 初版，六个场景胜出五个；另加三个未见过的场景（只改开头、退休老人生活记录、律师普法），各项多为 4–5 分。剩余问题（提问成固定动作、示范写成填空题、缺画面和时长、招生目标没给去哪找、结尾重复）已按评审意见再修一轮。
- 第三轮：这次修改对比上一版，12 个场景（新增改 AI 初稿、开源起名、二手车变现三个）只赢 5 个。更短、术语更少，但开头变平、没有钩子，还出现了把用户没提的道具当成有的情况。原因是“示范不能刻意”这条把助手推向了保守；“总”这个术语来自收丹模块自己的输出模板。
- 第四轮：针对第三轮的退步再修（示范也要有钩子、接住观众怀疑；用户给的事实写死，只空真不知道的一两处；没提到的东西不当成有；模板去掉“总”），对比第二轮的版本：12 个场景赢 7 个、输 4 个、平 1 个，总分 381 比 378。第三轮的退步已收回，没有发现新的明显问题。每个场景只跑一次，1–3 分的差距在正常波动范围内。
- 仍然存在的短板：最抓人的那一处（价格、关键步骤、要写的那个字）有时还是留空；开头偶尔只是“顺”；个别回复仍偏长、有凑数的备选。

## 本轮限制

- 测试员、评审员都是同一类模型，不等于真实用户；没有在 Claude Code、Codex、豆包等宿主里实际安装试用。
- Bot 精简版约 5 万字节，未核对具体宿主设定框的长度上限。
- 未做真实用户试用、拍摄发布或成交验证。
